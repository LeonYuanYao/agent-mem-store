# Jev 0.4 threshold validation

Date: 2026-09-21. Status: offline experiment only; no production integration or configuration changes.

## Decision

Keep 0.4 as a plausible experimental threshold, not a validated production default. On this fresh challenge set, 0.4 and 0.5 retain the same clearly relevant memories and admit the same labeled irrelevant memories. Lowering the threshold adds one borderline item. Both thresholds fail the predeclared query-level check: one request loses its only labeled relevant candidate.

This result supports continued evaluation of 0.4, but does not establish superiority over 0.5 or justify activation. Remaining questions concern the definition of useful supporting evidence and scope-incompatible information, not just the numerical threshold.

## Method

- 32 newly constructed requests, four candidates each: 128 unique request/candidate pairs. Four strata of eight requests cover supporting environment facts, applicability conditions, short conversational context, and same-word/different-task disambiguation.
- Fixed labels: 52 relevant, 8 borderline, 68 irrelevant. Thirty requests have at least one relevant candidate; two underspecified requests have none.
- The assistant authored labels and rationales before inference. There was no independent human annotation. No labels were changed after observing scores, and none were sent to Jev.
- No exact query was reused from the previous synthetic or historical replay datasets. These are constructed pools, not new production traffic or outputs of a fresh embedding retrieval run.
- Model: `jev-1.13.0`. Same Noul question and true/false criteria as the previous historical replay. Shared state contains the query and limited recent user context; each question contains only its own candidate.
- Primary run: 32 requests. Eight predetermined requests were each repeated twice, adding 16 requests. Repeats assess stability and are not counted as additional independent quality samples.
- Labels, thresholds, repeat selection and provisional checks were frozen before API calls. Fixture SHA-256: `e78691804fd0c081f02fc783f7b81bc03e59e63ad51a003d74ddf466c953320c`. Question SHA-256: `725521f7214fa3d90dcc3c2d74b5c96fa4421373e95014ef4032ba89abf294f3`.
- No live Vault/runtime fixtures, production writes, hook changes or activation. API requests used constructed, non-personal content. Requests were sequential with a 10-second experiment timeout and no retries.

## Primary results

Retention uses `score >= threshold`. Borderline items remain a separate category rather than being silently counted as correct.

| Metric | 0.4 | 0.5 |
| --- | ---: | ---: |
| Relevant retained | 51/52 (98.1%) | 51/52 (98.1%) |
| Borderline retained | 3/8 | 2/8 |
| Irrelevant retained | 2/68 | 2/68 |
| Irrelevant rejected | 66/68 (97.1%) | 66/68 (97.1%) |
| Total retained | 56/128 | 55/128 |
| Relevant-only share among retained | 91.1% | 92.7% |
| Requests retaining some relevant content, among requests with relevant candidates | 29/30 | 29/30 |

The only additional item at 0.4 is F11/c4, scored 0.49: “Test caches can usually be regenerated by business requests,” for a request to clear staging caches while leaving production untouched. Its frozen label is borderline: useful possible context, insufficient action guidance.

| Stratum | Relevant retained at 0.4 | Irrelevant retained at 0.4 |
| --- | ---: | ---: |
| Supporting environment facts | 16/16 | 0/16 |
| Applicability conditions | 7/8 | 2/16 |
| Short context | 12/12 | 0/20 |
| Same-word disambiguation | 16/16 | 0/16 |

The corresponding relevant/irrelevant counts at 0.5 are identical. Errors concentrate in the applicability-condition stratum; the aggregate percentages conceal this weakness.

## Cases and label uncertainty

| Case | Candidate and request | Score | Frozen interpretation |
| --- | --- | ---: | --- |
| F09/c1 | Request asks for a Memcached key's remaining TTL. Candidate says its protocol differs from Redis and to use the service's supported expiration diagnostics. | 0.31 | Relevant backend distinction, filtered at both thresholds. This is the sole relevant candidate for the query. |
| F12/c4 | Read-only migration-status request. Candidate describes the command that executes pending migrations. | 0.52 | Irrelevant under the frozen exclusion rule, retained at both thresholds. |
| F15/c1 | Run tests only in one monorepo package. Candidate explains that `pnpm -r test` runs tests across packages. | 0.87 | Irrelevant under the frozen scope rule, retained at both thresholds. |

These labels are contestable. F09 is vague guidance rather than an executable solution. F12 and F15 are factual descriptions of excluded actions and could help an agent explain what to avoid. Therefore the scores establish disagreement with the frozen rubric, not independent proof that the model is wrong or that the final agent would execute the wrong command. Retaining a fact is not authorizing an action.

Before a follow-up experiment, clarify whether explicit avoidance evidence is useful memory and how specific supporting facts must be. Apply the clarified rubric prospectively to fresh cases; do not relabel this run to make metrics pass. Simply moving between 0.4 and 0.5 does not resolve any of these three disagreements.

## Stability, latency and cost

The eight repeated requests cover 32 unique pairs. Across three observations per pair, neither threshold has any keep/drop flip. The largest score range is 0.03. This small preselected subset does not establish general stability for all scores close to the threshold.

All 48 API calls succeeded, without retries.

## Relationship to previous evidence

The [historical replay](jev-historical-relevance-replay-2026-09-21.md) retained 24 relevant, 16 borderline and 2 irrelevant pairs at 0.4, compared with 23 relevant, 12 borderline and 2 irrelevant at 0.5. That exploratory result motivated this test. The fresh constructed set adds one borderline pair but no additional relevant pair at 0.4. Do not pool their percentages as a production accuracy estimate: the sampling procedures differ.

The original [feasibility experiment](jev-relevance-feasibility-experiment-2026-09-21.md), historical replay and this challenge set test post-retrieval judgment. They do not measure whole-library recall, answer quality or an activated fallback path.
