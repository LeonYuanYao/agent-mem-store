# Dreaming：按需读取项目的对照实验

日期：2026-09-11。结论：项目读取有助于核验事实和限定适用范围，尚不足以支持自动合并或删除记忆。

## 方法与边界

从前一轮冻结的真实记忆中选择 9 条，组成仓库边界、source/debug 构建模式、权限与 MR 偏好三组。每组使用 Terra Low、default tier（非 fast），分别执行无项目证据和有项目证据的评估。两组评估的提示词、记忆和输出 schema 相同，输入差异仅为 evidence。

有证据组增加一次选文件请求：模型从 8 个相关文件的目录中选择至多 5 个，实验程序返回固定 HEAD 的原文及 Git 元数据。读取目录由主 Agent 预选，覆盖项目说明、Rush、子模块、package 和构建配置；这验证受控读取的收益，不代表模型能独立在全仓库搜索。底层模型 shell、MCP、浏览器、记忆等工具关闭，没有执行项目脚本。读取所用 Git 命令为只读命令。

外层 workspace 固定于 `<workspace-snapshot>`，内层 acme 固定于 `<project-snapshot>`。两者有未提交改动，文件证据通过 `git show <HEAD>:<path>` 获取，不包含这些改动，也不切换分支。元数据记录所选 checkout，结论不外推至其他副本。

主对照共 9 次调用（3 次基线、3 次选文件、3 次带证据评估）；另补 1 次权限压力测试，直接提供两层 AGENTS.md。文件内容只作为待核验材料，不作为对子模型的操作指令。

## 结果

| 主题 | 无项目证据 | 按需读取后 | 主 Agent 复核 |
|---|---|---|---|
| 仓库边界：sample-30、sample-12 | 当前事实未验证 | 选择 Rush 和子模块配置；结合 Git 元数据确认本 checkout 的父子仓边界，确认 Rush 和子模块配置 | 有实质帮助；保留分支范围，明确尚未确认 C++，没有强行合并互补知识 |
| 构建模式：sample-02、sample-14、sample-13 | 未验证，不整理 | 选择两层项目说明及配置解析、模板；获得 source/debug 的文档依据，提出合并 | 事实依据增加，但合并草稿扩大例外，拒绝采用 |
| 权限与偏好：sample-16、sample-19、sample-21、sample-11 | 保留各条；人工偏好属于政策 | 仅选择外层项目说明；保留各条，但建议重新确认人工 MR 偏好 | 保留行为合理，重复要求人类确认不合理，拒绝该注释建议 |

### 构建模式合并仍然错误

sample-14 原文的例外为“仅使用预构建 binary 且不改子模块源码时不适用”。合并草稿变成“binary 使用或不修改子模块源码的场景不适用该本地编辑保护要求”。这将 AND 改为 OR，扩大了不受保护要求约束的范围。因此，即使已经读过项目文档，该草稿也不能自动落地。

配置解析代码和模板提供的是配置机制及文档依据，本轮没有读取完整 reset 执行链路，也没有运行构建。不能把模型的 supported 状态当成实现行为已经验证。

### 人工政策不应依赖仓库佐证

带证据评估保留了 sample-11，却建议等待新的明确人类指令后验证 MR 平台偏好。该样本已经明确标为 human_authored；项目文件没有写这项偏好，不构成要求用户再次确认的理由。实验没有实际创建 Review Inbox 或提醒。

### 额外权限压力测试

主对照的选文件步骤没有读取内层 AGENTS.md，因此未遇到其中带有 reset 的分支切换步骤。额外一次调用直接提供两层文件，以检查模型会否采用这些步骤推翻冲突保护要求。

输出区分了分支切换流程和冲突处理规则，保留了人工 MR 偏好。它提出将三条冲突记忆合成一段，保留停止、现场、禁止批量解决、解释双方改动、等待批准、逐项处理等要求。主 Agent 初步逐条复核未发现明显丢项，但该建议的 evidenceIds 为空，模型也明确说未获得项目验证，因此不能把这个草稿的质量归因于项目证据。它只是一个可进一步 review 的离线草稿，尚未进行重复测试或源会话验证。

## 开销

| 三组调用合计 | 输入 token | 输出 token | 模型调用累计耗时 |
|---|---:|---:|---:|
| 无证据评估 | 34,423 | 1,398 | 48.5 秒 |
| 选文件 | 35,209 | 304 | 25.5 秒 |
| 带证据评估 | 52,755 | 2,637 | 68.8 秒 |
| 额外压力测试 | 19,988 | 964 | 24.0 秒 |

只读查证流程的选文件与评估合计输入 87,964、输出 2,941 token，累计 94.3 秒。相对基线，输入约 2.56 倍，调用耗时约 1.94 倍。此处是模型调用耗时，不包含主 Agent 的准备和复核。缓存、模型固有上下文和每次独立启动都有影响；本次两次调用读取整文件的实验方式不是生产成本下限。

所有 10 次调用正常结束。主对照检查未发现未知记忆 ID、未知证据 ID或业务输入差异；这些结构检查不等于语义正确率。样本很小、人工预选且没有已知过时知识的系统覆盖，不提供准确率或自动删除成功率。

## 建议

继续考虑“按需项目查证”，优先将结果保存在单独的核验记录中：文件版本、支持了哪些事实、未覆盖什么。不要将“这次没读到证据”等临时状态写入长期记忆正文。

自动整理仍需解决条件和例外的保真问题；本轮不能批准自动合并或删除。人工知识无需通过代码佐证才能继续有效。下一步若继续实验，可将自动产物限制为核验记录和整理草稿，避免新增人工确认噪音；原始记忆保持不变。

正式系统、Vault、SQLite 和业务仓库均未写入。仅新增临时实验脚本与本报告，没有 commit 或 push。
