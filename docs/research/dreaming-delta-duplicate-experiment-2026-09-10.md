# Dreaming 局部重复替换实验

> 公开版说明：项目名称、样本身份及私有仓库引用已匿名化，业务例子已泛化；实验汇总指标和结论保持原样。本次脱敏没有重新运行实验，私有输入不随仓库发布。sample-* 是报告专用别名，不能用于查询真实记忆。

日期：2026-09-10。基线 main / `dreaming-baseline-2026-09-10`。

## 结论

局部提案与原文保留让输出更容易检查，并从接口上避免了整组覆盖、错误重写 compact 的问题；**本轮真实样本没有获得可接受的缩减收益**。Luna 提出的唯一真实重复替换未完整保留用户可见的汇报要求，主代理拒绝接受。完全重复的人工构造对照成功识别，不能计入真实收益。

本轮把任务从广泛的互补综合收窄为“已有条目完全覆盖另一条时，保留原条目并提议替代重复项”。这不等于完整 Dreaming 已验证，也没有验证过时知识校正或运行统计清理。

## 优化内容

沿用同一份 21 条 acme project 冻结快照、同一版 Luna Medium、非 fast 配置，不读取生产库、不修改原条目。

- 输出仅包含局部替换提案；未提及条目默认不动。
- survivor 必须是输入中存在的记忆，正文和 compact 均不改写。
- 仅接受重复或被完整涵盖的内容，共同话题和互补信息不足以替换。
- 每项提案显式提供 trigger、objective、例外及其约束的操作。
- 对被替代条目逐条给出原文引句和 survivor 中对应引句。程序检查 ID、权威、scope、重复参与、引句是否真实存在；该检查不证明语义等价或全部条件已覆盖。
- 排除 Human-authored 和 review_due，不把源码缺失的历史记忆声明为已重新验证。

## 三组复测与自动近邻对

先复用上一轮自动生成的三个五条候选包，Luna 均返回空提案。允许不改动的结果是合理保护，但也没有带来缩减。

随后修正候选发现的一项限制：取消此前非重叠贪心包对邻居的占用，改为计算同一快照中所有符合条件条目对的相似度，自动选择最高的三个 pair。没有人工指定哪对应该合并。

| 试验 | 输入 | 结果 |
| --- | --- | --- |
| 原候选包 auto-1/2/3 | 每包 5 条 | 各无提案 |
| pair-1，余弦 0.9697 | sample-16、sample-19 | 无提案 |
| pair-2，余弦 0.9671 | sample-16、sample-21 | 无提案 |
| pair-3，余弦 0.9654 | sample-19、sample-21 | 提议用 sample-21 替代 sample-19；语义复核拒绝 |
| 人工构造正对照 | sample-02 与其完全相同的正文/description 副本 | 正确识别重复 |

正对照 ID `sample-33` 只存在于实验输入，标为 synthetic，未写 Vault 或 runtime。它验证能够识别完全相同的文本；不代表知识库存在这条真实记忆，也不证明两个不同 provenance 的实体在生产中可直接合并。

## 唯一真实提案的失败原因

sample-19 要求“列出冲突文件并说明双方改动”；sample-21 要求“应分析冲突文件及 ours/theirs 变化”。Luna 将后者作为前者的覆盖证据。

两段引句确实存在，ID 和 scope 检查也通过。但分析是一项处理动作，列出并说明还包含向用户提供信息的要求。保留后者并撤下前者，会丢失显式汇报约束。此次复核按“不丢独有要求”的实验标准拒绝替换。

这说明保留正文不变可以消除生成式重写的一类风险，但选择 survivor 时仍会遗漏语义义务。真实引句、相似度高和 schema 合法都不能替代完整覆盖验证。空提案也不证明没有可整理内容；模型拒绝时没有逐项给出所有差异，本轮不能据此评价近重复召回率。

## 后续判断

值得保留的是局部变更接口、原文保留、真实引句和程序约束。现阶段不建议继续通过增加宽泛提示词承诺自动去重质量。

若继续实验，优先用同一批固定条目对比较更强模型对“完整覆盖”的判断，并要求每个拒绝或接受结果都指出具体差异；把“分析”和“对用户说明”等独立义务纳入评估。只改变模型或裁判环节，避免同时变动分组、阈值、样本和提示词而难以归因。这是后续建议，本轮未擅自更换模型。

完全相同文本的处理应优先复用现有确定性去重，并仍检查 scope、权威、版本及来源语义，不值得额外引入 Dreaming 模型调用。
